# Hybrid Merchandising — логика прототипа

Прототип строится по принципу: **мерчендайзер управляет намерением витрины, система — её актуальным исполнением**.

## Базовый pipeline

`CATALOG → FILTER → RANK → CONSTRAINTS → CAPACITY → RESERVE → STOREFRONT`

1. **FILTER** — формируется пул кандидатов по отделу, категории, коллекции, новизне и минимальному остатку.
2. **RANK** — каждому кандидату рассчитывается коммерческий score по продажам L7D, наличию, новизне и скидке.
3. **CONSTRAINTS** — применяются ограничения visual merchandising: без дублей SKU, лимит одинаковых категорий и цветов.
4. **CAPACITY** — физическое количество слотов секции определяет, сколько товаров может быть показано.
5. **RESERVE** — все подходящие товары, которые не вошли в видимые слоты, остаются в ранжированном резерве.
6. **FALLBACK** — если товар становится недоступен, свободное место занимает следующий допустимый кандидат.

## Пример: 3 слота и 10 подходящих товаров

Секция имеет capacity = 3. Правила нашли 10 eligible SKU.

- показано: TOP 3 с учётом ranking и constraints;
- резерв: позиции 4–10;
- если один из TOP 3 становится OOS, система берёт следующий подходящий SKU из резерва;
- пустой слот не появляется, пока в резерве есть допустимый кандидат.

## HYBRID / AUTO / MANUAL

- **AUTO** — все свободные слоты наполняются системой.
- **MANUAL** — автоматическое наполнение отключено.
- **HYBRID** — свободные слоты наполняются автоматически, но любой слот можно вручную закрепить (`PINNED`).

`PINNED` занимает физическую ёмкость секции. Например, при 3 слотах и одном PIN система автоматически выбирает только 2 других товара.

## Правила автоматизации

Рабочие правила V4:

- Department / Category / Collection / Stock / New only — eligibility filters;
- веса ranking: L7D sales / stock / newness / discount;
- `NEW → boost`;
- `low stock → bury`;
- не повторять один SKU;
- не более N товаров одной категории;
- не более N товаров одного цвета;
- `PINNED → ranking не меняет позицию`;
- `PINNED OOS → temporary fallback / keep / collapse`;
- `no candidate → keep empty / collapse`;
- `overflow → TOP N + reserve`.

## Почему выбран товар

Для каждого заполненного слота интерфейс показывает происхождение и объяснение:

- `AUTO` — выбран системой;
- `PINNED` — закреплён человеком;
- `FALLBACK` — временно заменил недоступный PIN;
- `OOS` — оставлен несмотря на отсутствие остатка.

Панель «Почему этот контент в слоте» показывает причины: фильтры, score, наличие, L7D и соблюдение ограничений композиции.

## Региональная модель

Структура страницы и базовые правила считаются Global. Регион (`RU / KZ / GCC / WW`) использует ту же страницу, но может иметь override для ассортимента, наличия и контента. Это позволяет не создавать отдельную копию Best Sellers для каждого рынка.

## UI V4

Правая панель секции разбита на:

`Контент → Источник → Сетка → Рейтинг → Автоматизация → Fallback → Регион`

Сетка отвечает только за геометрию и capacity. Источник и правила отвечают за candidate pool. Рейтинг — за порядок. Автоматизация — за ограничения и boost/bury. Fallback — за поведение при OOS. Контент — за ручные PIN и editorial-вставки.
